# Route Task

## Resources and boundary

Read [shared governance](../../references/governance.md) before substantive work. Reuse the same version if already loaded. Apply the relevant [acceptance gates](../../references/acceptance-gates.md), [source discipline](../../references/source-discipline.md), and [output contract](../../references/output-contract.md).

Use the [deliverable template](../../templates/deliverable.md) only when useful. Follow actual user/project authority and available host capabilities.

## Inputs

Requested objective, authorization, artifact/version if supplied, evidence, scope, and acceptance criteria. Ask only for a material missing input; do not invent unavailable data or tool access.

## Workflow

1. Identify objective, artifact/version, authorization class, available inputs, and requested output.
2. Ask only about a gap that materially changes scope, conclusion, authority, or action. State non-critical assumptions and proceed.
3. Use analyze-evidence for evidence-dependent analysis; review-deliverable for scoped artifact review. Handle simple discussion directly when no specialist adds value.
4. Set one synthesis owner, dependencies, output expectations, acceptance criteria, and stop rule if work is split.
5. Return the selected workflow and a reviewable result within the authorized scope. Do not activate every capability or infer approval.

## Output and acceptance

A scoped task contract and consolidated output. PASS when routing is proportional and authorization is preserved. BLOCKED when a material ambiguity prevents the requested action. Report actual checks, decision-changing limitations, and authority status using the shared output contract. Stop when scope and required checks are complete.
