# Shared acceptance gates

Apply the gate to the actual scope. Failed material gates mean BLOCKED; disclose checks not performed rather than claiming they passed.

| Work | Fail when |
| --- | --- |
| Material analysis | A material claim has no evidence, assumption label, or explicit uncertainty; missing evidence is turned into absence of a fact. |
| Numeric analysis | Profit is equated with cash; an applicable bridge fails to reconcile; a plug is invented; recommendation robustness is asserted without evaluated sensitivities. |
| Professional-source conclusions | Current law/standard applicability is asserted without retrieval/status; a rate, paragraph, opinion, or procedure is invented. |
| Review | Review-only edits a baseline; polish changes numbers, conclusions, or authority without an authorized substantive delta. |
| State/runtime | Prompt instructions are presented as enforced permissions, confidentiality, transactions, monitoring, or persistence. |

Financial gates do not require a full model for a narrow non-model task. Unsupported definitive technical conclusions remain blocked. Add specialist gates only when the domain scope requires them.
