Use only when a project references or adopts an external governance source. This blank profile grants no authority.

- adoption_status: reference-only
- source_name:

- host_control_evidence_ref:
- unresolved_conflicts: []

`reference-only` supports research and comparison; it does not activate a governance engine. Use `adopted` only when explicit project/organizational authorization identifies scope and provisions. Adoption is not installation or conformance. Unknown applicability remains unresolved for the affected consequential action; routine reversible drafting may continue within its authorized scope.

Resolve conflicts through the designated owner; do not silently merge incompatible verdicts, state ownership, or authority rules. A new source version requires an explicit adoption delta, not automatic replacement.

For shared operating state, identify each entity's authoritative store, revision, writer, and consumer. If APOS coexists with AI Founder OS, map project state to the existing operating-state owner; do not create a second authoritative lifecycle ledger by default.
