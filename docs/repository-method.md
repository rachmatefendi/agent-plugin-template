# Repository specific development method

Copyright © 2026 Rachmat Efendi.

The method defined here is the project's concrete configuration of task contracts, evidence handling, scoped output dispositions, review convergence, and release evidence. Each step maps to authored repository material or working utilities.

## 1 Bind the objective before selecting capabilities

Record the requested output, authorization class, artifact version, inputs, and acceptance criteria. Use the smallest capability set that can complete that objective. A request to discuss or review does not authorize revision or execution.

## 2 Keep the evidence state explicit

Classify material claims and retain source context. Keep unknown, zero, absence, and not-applicable separate. Compute only supported quantities and preserve the distinction between verified arithmetic and unverified input data.

## 3 Apply objective bound disposition

Use the shared output contract to close consolidated output. A complete diagnosis can pass while a factual claim remains unconfirmed. If the user requested a definitive conclusion that lacks decisive evidence, block that conclusion rather than silently replacing the task.

## 4 Review against the fixed artifact

Bind findings to the artifact and criteria. Preserve accepted or locked content in review-only work. Separate material failed criteria from optional improvements. Revise only under a separately authorized substantive delta.

## 5 Separate execution evidence from grading

Keep raw prompts and actual outputs traceable. Record the task disposition separately from the behavioral outcome. A correct refusal can be a passing behavioral result. The validator requires non-empty actual output, a structured JSON evaluation record, matching case and input/output checksums, and complete criterion assessments. Grading quality and whether a run actually occurred remain the evaluator's responsibility.

## 6 Package the same bounded source

Customize identity without modifying the skills' behavior. Validate the source and package only plugin/ using reproducible archive metadata. Verify contained references and source integrity after extracting the archive. Include the copyright notice; keep development documentation and evaluation evidence separate from the installable package.
