# Release checklist

- [ ] Objective, scope, exclusions, host, authorization, audience, and owner are explicit.
- [ ] Skills have meaningful triggers, inputs, workflows, outputs, gates, and stop rules.
- [ ] Governance precedence and authority boundaries match the project.
- [ ] Sources, assumptions, and evidence gaps are traceable.
- [ ] Structural validator and utility tests pass against the release source.
- [ ] Extracted plugin archive references remain contained and valid; manifest and copyright notice match source.
- [ ] Executed case records have non-empty outputs, matching checksums, and complete criterion assessments.
- [ ] Required behavioral cases were executed with actual input/output evidence.
- [ ] Task dispositions and behavior outcomes are separate.
- [ ] Installed-host discovery/tools and requested artifact formats were tested, or their unverified status is stated.
- [ ] Runtime controls are claimed only where implemented and tested.
- [ ] Version, identity, audience, release notes, source commit, and archive agree.
- [ ] Material blockers are resolved; optional improvements do not reopen the baseline.
- [ ] Distribution rights and any public license were selected before public redistribution.

An RC-to-final metadata-only promotion can inherit unchanged RC evidence. Do not count inherited evidence as new execution. Publication, installation, adoption, and production readiness are separate statuses.
